## 总结

- **min 加速**算例(< -5%): 8/8
- **min 退化**算例(> +5%): 0/8
- **min 平均**: -20.6%
- **med 平均**: -39.8%
- **AC 最大加速**:ieee3w(30k 节点) min -42% / med -58%
- **AC ieee1w(10k 节点) min -37% / med -52%**
- **Hybrid(qinling_1000 80k 节点) min -7% / med -27%**

## 结论

**`result_mode='array'` 对大规模 AC 算例有显著加速效果。**

**AC 加速来源**(理论):
- `full` 模式:Newton 收敛后要把 `V/theta` 写回 `ppc["bus"][:, 7/8]` 数组,
  并触发 `_write_ppc_result_to_network` 把数据写回 Python 对象网络 (Network/Bus/Branch/...)
- `array` 模式:**完全跳过** `network.writeback` 路径(`ACPowerFlowCalc._network_writeback=None`)
- 30k 节点时 Python 对象写回的开销远大于 Newton 迭代本身,故收益显著

**Hybrid 收益较小**的原因:
- `qinling_1000` 80k 节点,Newton 迭代本身 0.6-0.9s,但 `HybridPowerNetwork.read_from_file` + `prepare` 占了 5-6s
- 模型构建时间主导端到端耗时,求解与写回占比小,故 array 模式加速有限

**使用建议**:
- 若只关心收敛性 + 节点电压/角度(取 `calc.result` 即可),**用 `array` 模式,加速 -27% ~ -58%**
- 若需要回填到 Python 对象网络做后续 SE/CA/AGC 等联动分析,必须用 `full` 模式
